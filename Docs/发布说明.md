# QJAR 工具 v1.1.3 发布说明

## 这一版修的反馈问题

- **编译输出实时可见**：构建脚本原来把 chroot 里的输出整体重定向进 `build.log`，只在结束时 `tail -12` 回显，界面上会长时间只有两行。现在用 `tee` 边编译边输出，完整的 make 进度和编译报错都会即时进入“构建日志”。
- **新增进度条与阶段文字**：按脚本打印的阶段标记（`编译：make modules` → `检查产物` → `打包：make tar` → `打包完成`）推进，阶段内每秒小幅前进，并显示“已用时 mm:ss”，长时间无输出也有反馈。
- 失败时日志保留全部内容，并额外提示退出码与最后一行；日志里的 stderr 行仍标红。
- 构建成功后日志里直接打印包的完整路径（`…\build-wsl\controller.xxxx\control_update.tar.gz`），配合「打开产物目录」不用再找。
- **修复环境检查误报“无法运行 wsl.exe”**：本机实测 WSL 发行版在空闲后的第一次调用要 10 秒左右，原来的 15 秒超时会被误判成启动失败。现在先做一次最长 90 秒的预热调用，并同时读取 stdout/stderr（避免 wsl 警告写满管道导致进程不退出）；失败时把 wsl 自己的报错带进日志，检查阶段也会显示“检查 WSL 环境…”，环境问题单独提示“环境不可用”。

## 这一版新增：编译页

第三个页面「编译」，用于内部编译控制器工程：

- 读取工程 `src/Makefile`，显示版本号、`DRIVER`、`SPACE`、`MOTION_TYPE`、`BUILD_KERNEL`。
- 版本号可改并写回 `src/Makefile`；只替换 `BUILD_MSG` 的赋值，行尾注释、换行和编码原样保留，写入走同目录临时文件后原子替换。
- 编译目标在「实体轴 `ETHERCAT_X86`」与「虚拟轴 `VIRTUAL_SERVO`」之间切换，同样写回 Makefile。
- 调用 WSL 里的通用入口 `/opt/qjar-build/build-controller.sh` 编译，日志实时显示，可取消。
- 勾选按「打包：开」时，编译成功后执行工程自带的 `make tar`，产出 `control_update.tar.gz`。
- 结果区显示版本、目标、产物数量、包大小与 SHA-256，并可打开产物目录。
- 与另外两页一致：写操作需要管理员登录；编译设置存在 `%LOCALAPPDATA%\QJAR\build.ini`。

## 实现要点

- Makefile 读写（`src/ui/ProjectMakefile.cs`）只认 `BUILD_MSG` / `DRIVER` 两个赋值行，按原编码与换行写回，不改动其它行。
- WSL 调用（`src/ui/Wsl.cs`）按原始字节读两条流：脚本输出是 UTF-8，`wsl.exe` 自身的管理消息是 UTF-16LE；`-d` 后的发行版名不能加引号（加了会报 `WSL_E_DISTRO_NOT_FOUND`）。
- 取消时先结束 `wsl.exe`，再按本次构建的工作目录名 `pkill`，避免影响同一发行版里的其它任务。
- 构建脚本（`405` 工程 `.scratch/405-multi-tool-follow/build-wsl.sh`）按 `DRIVER` 校验产物、补复制 `README`、新增 `--package` 并写 `result.json`。

# QJAR 工具 v1.0.0 发布说明

## 这一版做了什么

把原来两个独立工具合并成一个程序：**注册**（C + Win32 自绘）与**命令调试**（C# WinForms 自绘）。

- 一个窗口、一份侧栏；注册与命令调试是同一程序的左右两个页面，同一份控制器地址、同一次管理员登录。
- C 业务核心编成 `QJCore.dll`，界面通过 P/Invoke 调用；命令调试页也走同一套协议帧，线协议只有一份实现。
- 界面按 Astryx 设计系统重做：颜色、字号、间距、圆角、焦点、动效都取自 `astryx docs tokens-*`，映射表见 `Docs/astryx-ui-spec.md`。

## 相对旧版的行为变化

| 项 | 旧版 | 本版 |
| --- | --- | --- |
| 程序 | 两个 exe 分别分发 | 一个 `QJAR工具.exe` + `QJCore.dll` |
| 管理员口令 | 各自一份 | 统一为 QJROBOT，登录一次两页可用 |
| 命令发送 | 需管理员登录 | 同旧版，需管理员登录；未登录时按钮禁用并给出提示 |
| 重启示教器 | 只在注册成功后自动触发 | 注册页多一个「重启示教器」按钮，可单独触发 |
| 连接设置 | 各存各的 | `%LOCALAPPDATA%\QJAR\settings.ini` |
| 日志 | 各工具一份 | 每页各一份，可分别清空与导出 |

## 验收结果

- 通信冒烟（模拟控制器）：查询、注册（含 2 秒生效等待与轮询确认）、裸命令收发 3 项通过。
- 界面回归：普通用户发送命令被拒、查询后状态「未注册」、序列号、注册后「已授权 · 365 天」、命令回包显示、管理员口令 QJROBOT 通过、错误口令被拒、手动「重启示教器」经伪造 ssh 返回「重启命令已发送」。
- 体积：exe 106,496 B + dll 150,528 B ≈ 0.26 MB（目标 ≤ 2 MB）。
- 热启动 1.65–1.98 s（同机旧命令工具 2.5–3.0 s）。
- 空闲私有工作集 33.7 MB（原 30 MB 目标经确认为可放宽，建议以 60 MB 为上限）。

## 尚未验证

- 真实控制器的注册与重启（只用模拟控制器验证过协议与流程）。
- 125% / 150% 高 DPI 缩放（本机 100% DPI）。
- 现场 OpenSSH 环境（示教器 192.168.1.200 的 root 空密码登录）。

