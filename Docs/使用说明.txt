QJAR 工具 1.2.2
==============

解压便携包后，双击 QJAR工具.exe 即可运行。
QJAR工具.exe 必须与 QJCore.dll 放在同一目录。


一、注册一台设备
----------------
1. 侧栏不再显示地址。左下角齿轮“设置 → 连接地址”里可修改实体控制器与 Ubuntu 两套地址，
   并在顶部切换当前使用哪一套（注册、查询、升级用当前这一套；远程编译固定用 Ubuntu 这套），保存后立即生效。
   默认实体控制器 192.168.2.100:7625，Ubuntu 虚拟机 192.168.247.130:7625。
2. 点“查询状态”读取设备序列号与授权状态。
3. 首次使用时以普通用户身份运行，要注册设备请打开左下角齿轮“设置 → 账号”登录管理员。
   登录状态会被记住：关闭程序再打开仍然是管理员，直到在“账号”里点“退出管理”。
   设备未授权时点“注册设备”。注册写入完成后，程序会再次查询授权状态确认是否生效，
   然后自动重启在“示教器”卡中选中的目标。
4. “实体”固定指向 192.168.1.200。“本机虚拟”可选择 rbt_gui.exe，再点“打开示教器”或“关闭示教器”。
5. 操作过程中可以点“取消”停止本地等待；已经发出的注册请求无法撤回，请再用“查询状态”确认结果。


二、命令调试
------------
1. 点左侧“命令调试”标签切页。发送命令需要先做管理员登录，普通用户只能查看。
2. 输入命令，例如 getlic；有独立数据时填写“数据”。
3. 编码默认 UTF-8，点“编码：UTF-8”切换到 GBK；超时默认 5000 ms，可改 1-600000。
4. 点“发送命令”发出报文，“收发记录”显示请求和回包；点“清空”清除当前记录。


三、编译控制器
--------------
1. 编译页顶部切换“本机 WSL / Ubuntu 远程”。首次使用默认本机 WSL，工具会记住上次选择。
   本机 WSL 编译需要已安装 WSL 与
   /opt/qjar-build 里的隔离编译环境，并且先做管理员登录。
   第一次使用先点“环境准备”：五步命令（装 WSL 2、装 Ubuntu、恢复 32 位环境、装构建入口、验证）
   可以逐条“复制”，装好后点窗口里的“检查环境”确认。也可以直接运行 QJAR工具.exe --guide 打开这个窗口。
   窗口底部还有一段“给 AI agent 的提示词”，整段复制给能执行命令的 agent，它就能按步骤搭好环境并汇报结果。
   环境包约 318 MiB，在以下公开 Release 下载；解压密码由发布者授权提供：
   https://github.com/zizhuoruzi/qj-wsl-env/releases/tag/wsl-env-v1
   恢复脚本自动使用解压目录，包里自带构建入口，不用再查找 405 工程或改脚本路径。
2. 点“选择目录”指定控制器工程（含 src/Makefile 与 lib）。对话框从上次选的目录打开，重开工具也会还原工程。
   选到上级目录时会自动查找下三级的唯一工程；找到多个工程时提示你选具体目录，不擅自选择。
   查找跳过链接、隐藏目录和构建输出，最多检查 400 个目录。
3. “编译设置”显示 Makefile 里的版本号；编译目标用“实体轴 / 虚拟轴”按钮切换，选中的那个就是
   Makefile 里的 DRIVER。改版本号后点“保存”，写回工程的 src/Makefile；保存前会检查字符
   （字母、数字和 . _ - + 空格）。
4. “实体轴 / 虚拟轴”切换编译目标，对应 Makefile 里的 DRIVER = ETHERCAT_X86 与 VIRTUAL_SERVO，
   同样写回 Makefile。切换后请重新编译，产物会随目标变化。
5. “打包：开”表示编译成功后同时执行工程自带的 make tar，产出 control_update.tar.gz；
   点一下可切换成“打包：关”，只编译不打包。
6. 点“开始构建”，下方“构建日志”实时显示 WSL 的完整编译输出（含报错），
   进度条和“已用时”显示当前阶段（编译中 / 校验产物 / 打包中）；需要中止时点“取消”。
7. 成功后显示版本、目标、产物数量和包大小与 SHA256；点“打开产物目录”可查看
   工程下 build-wsl\controller.xxxx 里的 bin、rtlib、lib 与 control_update.tar.gz。
8. 远程模式使用左侧“Ubuntu 虚拟机”预设。先点“刷新目录”，再选源码目录、Ubuntu 项目和轴型。
   该模式可上传源码编译、打包下载，或对已有产物“仅打包”。虚拟轴支持启动和跟随控制器日志。
   工具会在停止目标项目的控制器前提示确认。
9. 点左侧“升级”可选择控制器或示教器升级包。确认框显示文件和目标 IP。
   控制器使用左侧当前预设，示教器固定为 192.168.1.200。上传完成表示包已写入并校验。


四、设置（左下角齿轮）
----------------------
1. 左侧分类：账号、连接地址、SSH 登录。地址任何用户都能改；账号里的口令与 SSH 两块需要先登录管理员。
2. 管理员口令默认 888999，“QJROBOT”始终可作为后备口令。改口令要先填当前口令，再两次输入新口令。
   忘记口令时删除 %LOCALAPPDATA%\QJAR\admin-password.dat，即回到默认口令。
3. 连接地址：实体控制器与 Ubuntu 虚拟机各一组 IP 和端口，保存后立即生效，侧栏同步显示。
4. SSH 登录：控制器、示教器、Ubuntu 各一组用户名和密码。密码按当前 Windows 用户加密保存；
   留空则仍用 OpenSSH 密钥或免密码登录。每组的“测试”会立即登录一次并显示结果，用于确认凭据可用。
5. 升级包上传使用控制器/示教器的 SSH 凭据，远程编译使用 Ubuntu 的凭据；注册后的示教器重启仍按系统 OpenSSH 默认方式。


五、界面说明
------------
- 状态区显示当前设备状态：等待查询 / 正在连接控制器 / 已授权 / 注册结果待确认 / 操作失败。
- 进度条显示本次操作的进度，下方左侧是状态说明、右侧是百分比。
- 提示条说明当前需要注意的事项，例如“注册请求已发出，结果未确认；请用‘查询状态’复查”。
- 注册页、命令调试页和编译页各有一份日志，可以“清空”，或点“导出日志”手动保存。
- 窗口高度不足时，编译、远程编译和升级页的日志卡会自动隐藏；放大窗口后恢复。
- 界面不显示、不保存完整注册码。


六、文件位置
------------
- 连接设置：%LOCALAPPDATA%\QJAR\settings.ini
- SSH 凭据：%LOCALAPPDATA%\QJAR\ssh-credentials.dat（按当前 Windows 用户加密）
- 编译设置（上次的工程目录、WSL 发行版、是否打包）：%LOCALAPPDATA%\QJAR\build.ini
- 导出的日志：保存到“导出日志”对话框中选择的位置。


七、系统要求
------------
- Windows 10 1809（64 位）及以上，支持高 DPI 显示器。
- 注册、调试、升级和 Ubuntu 远程编译不依赖 WSL；本机编译需要 WSL 2 和 /opt/qjar-build 里的隔离编译环境，
  环境准备见控制器工程里的《405_WSL编译环境》。
- 自动重启使用 Windows OpenSSH 客户端（系统可选功能），示教器需开放 SSH 22 端口并允许 root 空密码登录。
  首次连接记录 SSH 主机密钥；密钥变化会停止重启并在日志中报错。
  “重启命令已发送”表示示教器已接受命令，不表示开机完成；SSH 失败不会改变控制器已激活的结果。
